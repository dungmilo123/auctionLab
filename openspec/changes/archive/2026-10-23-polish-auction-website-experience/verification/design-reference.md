# Implementation reference

The collection is the focal point. Keep the accepted viewing-room palette:
ivory #F6F1E8, charcoal #24211E, burgundy #722F37, olive #62664D, brass #A38355,
white #FFFFFF. Noto Serif titles, Noto Sans text/controls, tabular amounts.
Type roles: 14 / 16 / 18 / 24 / 32 / 48 / 64 px. Spacing: 8 / 12 / 16 / 24 /
32 / 48 / 64 px. Left-aligned prose, restrained rules, white image mats.

```
Desktop home: navigation + language + search/saved/account
  story / heading / exploration | first featured collection's large image
  featured collections (cover-led) / nearest-close objects / suggestions
  categories / short brand footer

Desktop lot: title and collection link
  wide inspection gallery | current price, closing time
                          | condition + full shipping/pickup disclosures
                          | save and eligible bid submission
  story / specifications / history / related objects

Mobile: brand + language + menu
  heading / image / thumbnails / current price + close
  complete condition + fulfillment / save + bid
  story + specifications + history
```

Annotation: a single leading event provides the image/story anchor; never insert
sample collections when empty. Object cards use large images and concise schedule
metadata. Bid and order review get functional emphasis; no universal card frame.
The mobile flow retains full disclosures before submission. Menus and inspection
use 240 ms panels, feedback 150 ms, home entrance at most 650 ms. No idle motion.

Baseline critique: the static camera competes with the actual collection,
capability inventories dominate the top/footer, and cards repeat long schedules.
Replace these with a collection story, compact metadata and contextual recovery.
Do not use repeated uppercase labels or diamond ornaments. No design departure.
